# Рев'ю проєкту «Портал працівника» + бекенд Apps Script

Дата: 2026-08-28

Огляд охоплює три частини системи:

- **Фронтенд** — репозиторій `YuriyBuz/portal` (`index.html`, `admin.html`, `schedule.html`, `extra_shift.html`, `tests_manager.html`, `sw.js`).
- **Бекенд** — Google Apps Script (`doPost` + модуль «Штрафи та премії»). Коду немає в git — він живе в редакторі Apps Script, тому виправлення нижче подані як готові до вставки функції.
- **Таблиці** — головна `1t3vF0Vt…` (вкладки «Активні», «Адміністрація», «Сесії», «Заявки», «Логи», «Штрафи премії», «Довідник порушень») і графік `1uL5lkZG…`.

> **Готовий до вставки бекенд:** [`apps-script/Code.gs`](../apps-script/Code.gs) — повна виправлена версія, замінює старий `Code.gs` цілком. Файл `Penalties.gs` не змінюється.

Тобто будь-який працівник, залогінившись у портал і взявши свій токен із `sessionStorage`,

**Виправлено** у `apps-script/Code.gs`: кожен із цих запитів тепер починається з

### 1. Логіни та паролі з «0» не приймаються (головна скарга)

**Корінь проблеми — у таблиці, а не в застосунку.** Google Sheets будь-яке суто-цифрове значення трактує як число й **відкидає провідний нуль та форматування**. Це видно прямо в даних вкладки «Активні»:

| Працівник | Логін/пароль у таблиці | Мало б бути |
|---|---|---|
| Гончарук (логін) | `508328999` | `0508328999` — губиться `0` |
| Ісаченко (логін) | телефон `077-192-77-97`, логін `771927797` | `0771927797` |
| Рашидов (пароль) | `9` | `09` — губиться `0` |
| Миняйло О. (пароль) | `505` | `0505` — губиться `0` |

Далі бекенд у блоці `login` читає це число і порівнює **як рядок**:

```js
var cleanActiveLogin = activeLogin.replace(/[\s\-]/g, '');   // "508328999"
if ((inputLogin === activeLogin || cleanInputLogin === cleanActiveLogin) && inputPassword === activePass)
```

Працівник вводить свій телефон **із нулем** (`0508328999`), а в таблиці лежить `508328999` → рядки не збігаються → «Невірний логін або пароль». Те саме з паролем `09` vs `9`.

Проблема «сприймається і таблицею, і додатком» саме тому, що:
1. **Таблиця** сама втрачає нуль у момент запису (клітинка числова).
2. **Додаток** читає вже зіпсоване значення й порівнює буквально.

**Виправлення (три рівні, усі вже застосовані в `apps-script/Code.gs`):**

1. **Толерантне порівняння** при вході — `loginMatches_()` / `passwordMatches_()` порівнюють ще й «цифри без провідних нулів». Це лагодить **уже наявні** зіпсовані рядки без ручного втручання.
2. **Профілактика на запис** — у `update_credentials` та `add_employee` виставляти клітинкам текстовий формат `@` **перед** `setValue`, щоб нові логіни/паролі не втрачали нуль.
3. **Разова функція** `fixCredentialColumnsToText()` — переводить колонки телефону/логіну/пароля у текстовий формат назавжди. ⚠️ Вона зупиняє подальшу втрату нулів, але **не відновлює вже втрачені** — такі рядки треба один раз перевписати вручну (тепер нуль збережеться).

### 2. Головна таблиця з паролями відкрита «всім, хто має посилання»

Перевірка прав доступу:

```
Головна таблиця 1t3vF0Vt… → permissions: { type: "anyone", role: "reader" }
```

У вкладці «Активні» **паролі й логіни зберігаються у відкритому вигляді** разом із телефонами, датами народження та екстреними контактами. Оскільки таблиця читається будь-ким за посиланням — це витік персональних даних усіх працівників.

Головну таблицю бекенд читає **лише на сервері** (її ID немає у фронтенді), тому публічний доступ їй **не потрібен** — на відміну від таблиці графіка `1uL5lkZG…`, яку `schedule.html` тягне через `gviz` прямо з браузера (їй публічний read справді потрібен).

**Виправлення:**
- Головну таблицю (`1t3vF0Vt…`) прибрати з «anyone with link», лишити доступ лише власнику/бекенду.
- За можливості — не зберігати паролі відкритим текстом (хоча б хеш); як мінімум обмежити доступ до вкладки «Активні».

## 🟠 HIGH

### 3. Багатоденні відпустки/лікарняні позначають у графіку лише ПЕРШИЙ день

`extra_shift.html` для відпустки/лікарняного відправляє діапазон: `date = "12.08.2026 - 15.08.2026"`. Бекенд у `updateShiftStatus` бере **лише перший збіг** регулярки:

```js
var dateMatch = cleanDate.match(/^(\d{1,2})[\.\-](\d{1,2})[\.\-](\d{2,4})/); // → 12.08.2026
```

Тому при схваленні в графіку позначкою `В`/`Л` заповнюється **тільки 12-те число**, а 13–15 лишаються порожніми. Керівник вважає, що відпустку проведено на весь період.

**Виправлення:** розпізнавати діапазон `d1 - d2` і проходити циклом усі дні (з переходом через межу місяця). Хелпер `getDatesInRange_()` уже під'єднано до `updateShiftStatus` у `apps-script/Code.gs`.

### 4. Картка «Навчальні відео» веде на 404

`index.html` містить `<a href="videos.html">`, але файлу `videos.html` у репозиторії немає. Натискання → «сторінку не знайдено».

**Виправлення:** створити `videos.html` або тимчасово прибрати/задизейблити картку.

### 5. Гонки при генерації ID (немає блокування)

`submit_request` і `add_employee` рахують `nextId = Math.max(...ids) + 1` **без `LockService`**. Дві одночасні заявки отримають однаковий ID. Показово, що модуль штрафів (`add_penalty`) вже використовує `LockService.getScriptLock()` — тобто в проєкті є асиметрія: частина ендпоінтів захищена, частина ні.

**Виправлення:** обгорнути генерацію ID + `appendRow` у `LockService.getScriptLock()` так само, як у `add_penalty`.

### 6. Новому працівнику дефолтний логін теж псується нулем

`add_employee` пише `defaultLoginAdd = phone.replace(/\D/g,'').slice(-10)` (напр. `0956779460`) звичайним `appendRow`. Значення суто-цифрове → Sheets одразу перетворює на число й губить нуль. Тобто **щойно створений** працівник уже не зможе увійти за автологіном. Лагодиться пунктом 1 (текстовий формат на запис).

## 🟡 MEDIUM

### 7. `doOptions` / CORS: нефункціональний код

```js
function doOptions(e) {
  return HtmlService.createHtmlOutput("").setHeader("Access-Control-Allow-Origin", "*") …
}
```

У Apps Script `HtmlOutput` **не має методу `.setHeader()`** — цей код кинув би виняток, якби викликався. Він не викликається лише тому, що фронтенд шле `Content-Type: text/plain`, а це «простий» CORS-запит без preflight. Висновок: увесь CORS-блок оманливий і не робить того, що здається.

**Ризик:** якщо колись змінити `Content-Type` на `application/json`, браузер відправить preflight `OPTIONS`, Apps Script його не обслужить — усі запити впадуть. Варто лишити коментар-попередження або прибрати мертвий блок.

### 8. Плутанина «3» (цифра) vs «З» (кирилиця) у графіку

- `updateShiftStatus` при схваленні додаткової зміни пише **цифру** `'3'`.
- Ручне редагування (`edit-cell-modal`) пропонує **кирилицю** `'З'`.

Обидва інтерпретуються (`checkType`, кольори в `renderSchedule`), але в таблиці накопичуються різні символи для однієї суті. Легко зробити помилку в майбутніх правках/формулах.

**Виправлення:** уніфікувати на одному символі (рекомендовано `З`) у `updateShiftStatus`.

### 9. Неоднозначність ПІБ (батько/син)

У «Активні» є `Максімюк Анатолій Анатолійович` (син) і `Максімюк Анатолій Вікторович` (батько). `sameEmployee()` / `resolveEmployeeName_()` матчать за словами: скорочене «Максімюк Анатолій» збігається з **обома**. Автори частково це передбачили (`matches.length === 1`), але штраф/премія, записані під скороченим ПІБ, у картці відобразяться в обох. Ризик неправильного нарахування.

**Виправлення:** для штрафів/премій зберігати й звіряти повний ПІБ (як у «Активні»), а не скорочений із графіка.

### 10. Схвалення додаткової зміни перезаписує наявну робочу зміну

`updateShiftStatus` при `'Погоджено'` робить `cell.setValue('3')`, затираючи попереднє `'1'`. При подальшому відкаті (`'Відхилено'`/`'Очікує'`) клітинка **очищується повністю** — початкова робоча зміна `1` втрачається безповоротно.

### 11. `tests_manager.html` нічого не зберігає

Форма додавання тесту лише вставляє `<li>` у DOM (`list.appendChild`), без запиту на бекенд. Після перезавантаження сторінки всі додані тести зникають; список статичний (два хардкод-посилання). Функціонал фактично неробочий.

### 12. Вкладка «Сесії» росте безмежно

Кожен вхід додає рядок; прострочені токени видаляються лише коли хтось випадково спробує ними скористатися. З часом — тисячі рядків і повільніший `validateSession` (він читає весь діапазон лінійно на кожен захищений запит).

## 🟢 LOW / якість коду

- **13.** `generateSecurePassword()` = `Math.random().toString(36).slice(-8)` — не криптостійкий, може бути коротшим за 8 символів, а якщо вийде суто-цифровим — знову втрата нуля. Краще генерувати з гарантованим набором символів (літера + цифри).
- **14.** `index.html` при завантаженні редіректить в `admin.html`/показує застосунок **не перевіряючи токен** на сервері — прострочена сесія покаже оболонку, і лише перші запити впадуть із «Unauthorized».
- **15.** `sw.js` кешує лише `index/schedule/extra_shift` — `admin.html` та `tests_manager.html` офлайн недоступні (для адмінки це, ймовірно, і не потрібно, але варто усвідомлювати).
- **16.** У `update_credentials` немає перевірки на порожні `newPhone`/`newPassword`; «перевірка безпеки на дублікат» спрацьовує лише коли збігаються **водночас** логін І пароль з іншим працівником — тобто фактично не гарантує унікальності логіна.
- **17.** Токен сесії живе в `sessionStorage` і передається в тілі кожного POST — прийнятно для цього рівня, але варто пам'ятати, що це не «сесійна кука» й вразливе до XSS на сторінці.

## Застосунок «Облік ЗІП: Механік» (цей репозиторій, `index.html`)

Окремий застосунок; переглянуто побіжно:

- **XSS-ризик (низький):** `renderItemsList`/`renderHistoryList` вставляють дані з таблиці (`item.model`, `item.equipment`, `supplierName`, `supplierPhone`) через `innerHTML` без екранування. Якщо в клітинку потрапить HTML — виконається. Джерело — власна таблиця механіка, тож ризик невисокий, але варто екранувати.
- `showCustomDialog` свідомо використовує `innerHTML` для повідомлень (закоментовано «Дозволяємо HTML») — тримати сторонні дані подалі від нього.
- `MOCK_DATA` як фолбек: якщо бекенд недоступний, є ризик показати демо-залишки як реальні — варто явно маркувати демо-режим.
