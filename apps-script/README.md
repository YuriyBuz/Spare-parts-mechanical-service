# Серверна частина «Облік ЗІП»

| Файл | Призначення |
|---|---|
| `Code.gs` | **Єдиний файл скрипта**: автентифікація за PIN, `doGet`, `doPost`, план закупки. Замінює попередню версію повністю. |
| `migrate_structure.gs` | Одноразова міграція структури таблиці. Після успішного запуску **видалити з проєкту**. |

> ⚠️ У проєкті має лишитися **тільки `Code.gs`**. `migrate_structure.gs` і колишній `Auth.gs`
> оголошують ті самі константи (`LOG_SHEET_NAME`, `USERS_SHEET_NAME`), тож якщо залишити їх поруч,
> Apps Script відмовиться завантажувати проєкт через повторне оголошення.

## Порядок дій

1. **Резервна копія** таблиці — «ЗІП мех служба (backup …)» у Диску.

2. **Міграція структури.** Додати `migrate_structure.gs`, виконати `migrateStructure()` з `DRY_RUN = true`,
   звірити звіт, потім `DRY_RUN = false` і виконати ще раз. Після цього файл видалити з проєкту.

3. **Код.** Вміст `Код.gs` у проєкті замінити на `Code.gs` із цієї теки. Інших файлів у проєкті бути не повинно.

4. **Розгортання.** Розгортання → Керування розгортаннями → олівець → **Версія: Нова версія** → Розгорнути.
   Без створення нової версії за URL і далі працює старий знімок коду.
   Налаштування: «Виконувати як: я», «Доступ: будь-хто» — інакше браузер не прочитає відповідь на вхід.
   **URL веб-застосунку не змінюється**, правити `GOOGLE_SCRIPT_URL` в `index.html` не треба.

5. **Перевірка розгортання.** Відкрити в браузері `<URL>?action=ping` — має відповісти:
   ```json
   {"success":true,"version":"zip-2026-08-22-auth","auth":true,"employeesSheet":"ok"}
   ```
   `auth:false` → розгорнуто старий знімок коду (поверніться до кроку 4).
   `employeesSheet:"немає доступу"` → скрипт не має прав на таблицю `gw-ref`: відкрийте редактор,
   запустіть `auditPins()` вручну і дайте дозвіл у діалозі Google.

6. **PIN-и.** Виконати `auditPins()` з редактора: функція покаже, хто має доступ до ЗІП і де PIN дублюються.
   **Поки трьом механікам не призначено власні PIN у колонці Q аркуша `_REF_Employees`, вони не увійдуть** —
   у всіх трьох стартовий `1111`, і система свідомо відмовляє, щоб не записати операцію на випадкову людину.

7. **Фронтенд.** Викласти оновлений `index.html`.

8. **Щотижневий звіт.** Один раз виконати `setupWeeklyReport()` з редактора — створює тригер
   на понеділок 08:00 і прибирає старі тригери попередніх версій.

9. **Адресне зберігання.** Один раз виконати `setupStorageColumn()` з редактора — функція додасть
   колонку O «Місце зберігання» на всі аркуші-каталоги. Ідемпотентна; можна не виконувати взагалі —
   колонка створиться сама при першій зміні адреси з застосунку.

10. **Адреси розсилки.** Заповніть колонку **O «email»** в `_REF_Employees` для тих, хто має
    роль `zip.admin` або `admin` — саме звідти беруться отримувачі звіту. Перевірити список:
    `auditRecipients()` з редактора. Аркуш «Користувачі» лишається запасним джерелом.

## Перемикачі

| Константа | Типово | Що робить |
|---|---|---|
| `SKIP_UNCOUNTED_POSITIONS` | `true` | Позиція з порожньою коміркою залишку вважається неінвентаризованою і не потрапляє в план закупки (на 22.08.2026 це 48 рядків зі 189). `false` повертає стару поведінку. |
| `FALLBACK_EMAILS` | дві адреси | Куди слати, якщо ні в довіднику, ні в «Користувачах» адрес немає. |
| `ROLE_PERMISSIONS` | див. нижче | Роль → дозволені дії. `zip.use` — лише видача і скасування власних операцій; `zip.admin` і `admin` — плюс поповнення, інвентаризація, звіт, адреси зберігання. |
| `EXCESS_FACTOR` | `5` | Поріг блоку «Надлишок» у звіті. |
| `MOVEMENT_DAYS` | `7` | Період блоку «Рух» у звіті. |
| `ASSET_SHEET_PREFIXES` | Інструменти, Контейнер… | Аркуші основних засобів — не потрапляють у план закупки. |
| `SESSION_TTL_MINUTES` | `720` | Верхня межа життя сесії. Незалежно від неї застосунок виходить через 10 хв бездіяльності (`IDLE_LIMIT_MS` в `index.html`). |
| `EMPLOYEES_SPREADSHEET_ID` | `gw-ref` | Таблиця з аркушем `_REF_Employees`. |

## Якщо щось не працює

| Симптом | Причина |
|---|---|
| `loginWithPin_ is not defined` | Розгорнуто старий знімок коду або в проєкті немає актуального `Code.gs`. Кроки 3–4, перевірити через `?action=ping`. |
| `Identifier 'LOG_SHEET_NAME' has already been declared` | У проєкті лишився `migrate_structure.gs` або `Auth.gs`. Видалити. |
| Вхід каже «PIN закріплений за кількома співробітниками» | Дублікат PIN у колонці Q. Крок 6. |
| Вхід каже «Сервер недоступний» | Розгортання не «Доступ: будь-хто» — браузер не може прочитати відповідь. |

## Що НЕ входило в цю зміну

Дефекти з `docs/zip-accounting-audit.md`, які лишаються актуальними: адресація позиції номером рядка
і зіставлення за назвою моделі, обмеження історії 100 записами, дата за UTC,
`≤` і примусова «1» у розрахунку обсягу замовлення.

Закрито: гонка одночасних записів (`LockService`), подвійне списання з офлайн-черги
(ідентифікатор операції), мовчазне списання в мінус, нуль проти «не інвентаризовано».

Як влаштована сесія — `docs/zip-auth-session.md`.
Як працюють операції — `docs/zip-usage-operation.md`.
Адресне зберігання — `docs/zip-storage-addressing.md`.
Звіт на пошту — `docs/zip-report.md`.
