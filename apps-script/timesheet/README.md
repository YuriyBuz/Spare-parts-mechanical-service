# Автоматичний табель — Google Apps Script

Скрипт для таблиці-табелю з помісячними аркушами («Січень 2026», «Лютий 2026» …).

## Що робить

1. **Наприкінці місяця автоматично створює аркуш наступного місяця** копією
   попереднього: зберігаються формат, формули підсумків, групування працівників
   за посадами.
2. **Переносить усіх працівників з минулого місяця**, очищає години, переписує
   дати й дні тижня, підганяє кількість колонок під довжину місяця
   (28/29/30/31 день × «День»+«Ніч»).
3. **Звіряє ПІБ з довідником працівників** (аркуш `_REF_Employees`) і
   **проставляє `emp_id`** — у поточному та всіх наступних місяцях.
4. **Надсилає адміністратору лист** зі списком змін і невідповідностей.
5. Дає **кнопку ручного запуску** з підтвердженням і звітом на екрані.

## Структура аркуша, з якою працює скрипт

```
рядок 1        A1 = «Серпень 2026» + легенда (В / Л / Х …)
рядок 2        дати 1/8, 2/8 … (кожна на 2 колонки) + «за місяць»
рядок 3        дні тижня
рядок 4        «День» / «Ніч» для кожної дати, далі «Змін» / «Годин»
нижче          A = ПІБ, B = посада, C = emp_id, далі години по днях
```

Розкладка визначається **за вмістом**, а не за жорсткими номерами колонок:
скрипт шукає рядок із «День»/«Ніч», дати вигляду `1/8` над ним і `за місяць`
після днів. Тому він витримує зсуви колонок, а якщо шапку переробити
принципово — чесно зупиниться з поясненням, а не зіпсує дані.

## Встановлення

1. Відкрити таблицю табелю → **Розширення → Apps Script**.
2. Створити файли з такими самими назвами й вставити вміст:
   `Config.gs`, `MonthSheet.gs`, `Roster.gs`, `Report.gs`, `Main.gs`
   і **HTML-файл** `Sidebar` (без розширення в назві — Apps Script додасть `.html` сам).
3. ⚙ **Налаштування проєкту** → увімкнути «Показувати файл маніфесту
   `appsscript.json`» → замінити його вмістом з цієї теки.
4. Зберегти, оновити вкладку з таблицею — з’явиться меню **⏱ Табель**.
5. **⏱ Табель → ⚙️ Перші налаштування** — вставити посилання на довідник
   працівників і пошту адміністратора. Зберігається у властивостях скрипта,
   у коді жодних ID немає.
6. **⏱ Табель → 🆔 Проставити emp_id** — перший запуск. Google попросить дозволи
   (таблиці, пошта, тригери) — погодитись.
7. **⏱ Табель → ⚙️ Увімкнути автостворення** — створює щоденний тригер.

> Встановлювати має обліковий запис із правами **редактора обох таблиць**:
> тригер працює від імені того, хто його створив. Якщо немає прав на запис у
> довідник, поставте `WRITE_ALIASES = false`.

## Кнопка ручного створення

Три способи, усі роблять те саме й показують однаковий звіт:

* **Меню** ⏱ Табель → *➕ Створити аркуш наступного місяця* — питає
  підтвердження, після виконання показує результат у діалозі.
* **Бічна панель** ⏱ Табель → *🎛 Панель керування* — кнопки з результатом просто
  на панелі, плюс поле «інший місяць» (`2026-10` або `Жовтень 2026`).
* **Кнопка-малюнок на аркуші**: *Вставка → Малюнок* → намалювати прямокутник із
  написом «Створити табель на наступний місяць» → *Зберегти* → клікнути на
  малюнок → ⋮ → *Призначити скрипт* → ввести `manualCreateNextMonth`.

## Автоматичний запуск

Тригер `dailyEndOfMonthCheck` спрацьовує щодня близько 23:00 і діє лише двічі
на місяць:

* **в останній день місяця** — створює аркуш наступного місяця;
* **1-го числа** — страховка: створює поточний місяць, якщо його ще немає.

Повторний запуск нічого не дублює: якщо аркуш уже є, скрипт лише перезвіряє ПІБ.

## Налаштування

⚙ **Налаштування проєкту → Властивості скрипта**, ключ = назва параметра.
Правити `Config.gs` теж можна, але тоді ID потраплять у код.

| Параметр | Типово | Опис |
|---|---|---|
| `REF_ID` | — | довідник працівників: посилання або ID. **Обов'язково** |
| `ADMIN_EMAILS` | — | отримувачі звіту, через кому |
| `TIMESHEET_ID` | — | потрібен лише для окремого (standalone) проєкту; для скрипта всередині таблиці лишається порожнім |
| `EMP_ID_FROM` | `2026-08` | з якого місяця проставляти `emp_id` |
| `AUTO_ADD_NEW_EMPLOYEES` | `false` | додавати в табель активних працівників з довідника, яких там немає (у групу з такою ж посадою). Типово — лише повідомляти |
| `AUTO_REMOVE_FIRED` | `false` | зарезервовано; рядки звільнених ніколи не видаляються автоматично |
| `FUZZY_MAX_DISTANCE` | `2` | скільки помилок у написанні ПІБ пробачати |
| `FUZZY_AUTO_APPLY` | `true` | проставляти `emp_id` за нечітким збігом (у звіті позначається «перевірте») |
| `WRITE_ALIASES` | `true` | записувати знайдені варіанти написання в аркуш псевдонімів довідника |
| `ADD_NOTES` | `true` | примітки до комірок ПІБ з описом проблеми |
| `CLEAR_NAME_NOTES` | `true` | очищати примітки ПІБ при створенні нового місяця |
| `WRITE_LOG` | `true` | журнал запусків у прихованому аркуші `_Журнал_табелю` |
| `SEND_EMAIL_ON_MANUAL` | `true` | слати лист і при ручному запуску |
| `TIMEZONE` | `Europe/Kyiv` | часовий пояс тригера |

## Як звіряються ПІБ

По черзі, до першого однозначного збігу:

1. `emp_id`, який уже стоїть у рядку;
2. аркуш псевдонімів довідника (`варіант написання` → `emp_id`);
3. **ПІБ повне**;
4. **ПІБ короткий**;
5. **прізвище + ініціали** — «Гончарук Ольга Михайлівна» = «Гончарук О. М.»;
6. **нечіткий збіг** — те саме прізвище й не більше `FUZZY_MAX_DISTANCE`
   відмінностей у решті ПІБ.

Перед порівнянням ПІБ нормалізується: регістр, подвійні та нерозривні пробіли,
різні апострофи (`’ ‘ ʼ '`) і латинські літери-двійники кирилиці (`i`, `o`, `e`,
`p`, `c`, `x`, `K`, `M`, `T`, `H` …), які часто трапляються при копіюванні.

Якщо кандидатів кілька — `emp_id` **не** проставляється, рядок іде у звіт як
«неоднозначний збіг». Скрипт нічого не вгадує.

## Що потрапляє в лист

* аркуш, джерело, кількість днів і працівників, скільки `emp_id` проставлено;
* **немає в довіднику** — ПІБ є в табелі, у `_REF_Employees` немає;
* **нечіткий збіг** — розбіжність у написанні (з обома варіантами й «відстанню»);
* **неоднозначний збіг** — кілька кандидатів;
* **звільнені за довідником** — рядок залишається (місяць міг бути відпрацьований
  частково);
* **розбіжність посади** — у табелі одна, у довіднику інша;
* **дублікати** ПІБ або `emp_id` в межах аркуша;
* **є в довіднику, немає в табелі** — активні працівники з посадою;
* **невідомий / чужий `emp_id`**;
* **зміни структури** — додані чи вилучені колонки днів, додана колонка `emp_id`,
  очищені підсумки;
* **зауваження до довідника** — дублі `emp_id`, активні без посади.

Якщо все чисто — у листі так і написано, тема починається з ✅ замість ⚠️.

## Перевірка логіки без Google

```bash
node test/run-tests.js
```

`test/mock.js` підміняє `SpreadsheetApp`, `MailApp`, `Utilities`;
`test/fixture-month.csv` — знеособлена копія реального місячного аркуша
(структура 1-в-1, ПІБ вигадані). 53 перевірки: розпізнавання розкладки,
створення місяця з 31 → 30 днів і з 30 → 31, очищення годин, `emp_id`,
усі сценарії звірки, ідемпотентність повторного запуску, лист.

## Про що варто знати

* **`emp_id` вставляється колонкою `C`**, одразу перед днями: `A` — ПІБ,
  `B` — посада, `C` — `emp_id`. Колонки днів зсуваються праворуч на одну;
  формули підсумків Google Таблиці переставляють самі. Якщо на табель зав’язані
  зовнішні інтеграції з жорсткими адресами колонок — їх треба перевірити.
* Скрипт **не чіпає** формули підсумків «Змін»/«Годин»: очищаються лише комірки,
  де замість формули стояло число.
* Якщо праворуч від «Годин» у шапці лишились зайві `День/Ніч/Змін/Годин` від
  старішої розкладки — при створенні нового місяця вони прибираються.
* Ліміт Gmail на листи зі скрипта — 100/добу для звичайних акаунтів
  (1500 для Workspace). Скрипту потрібно 1–2 листи на місяць.
